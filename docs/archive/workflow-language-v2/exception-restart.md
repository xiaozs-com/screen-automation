# 未匹配异常的可选从头执行

本能力由流程明确启用，默认关闭，仅用于流程语言 v2（Markdown）步骤调度。
Windows 与 macOS 使用同一个运行引擎。任意 Python 入口不能据此安全地从头重跑，未增加此行为。
依赖 Agent/VLM 分类时，必须先确认 Agent 接入组件已安装、激活、启用且连接有效；
条件不满足时按现有界面提示获取授权码、激活和安装，不将草稿描述为当前可运行。

## 配置

在已有基本信息中加入引擎能力；有其他能力时一并保留：

```markdown
## 基本信息
- 引擎能力：exception-restart@1

## 异常处理
- 识别指令：识别当前异常；有已配置类型则返回该类型，没有则返回未知。
- 超时：360 秒
- 未匹配处理方法：从头执行
- 异常重启上限：3次
- 达到上限：终止流程
```

以上是配置片段，需要与流程的标识、锚定窗口、普通执行步骤等共同使用。
“识别指令”和“超时”可省略，启用本兜底时提供默认分类指令和 300 秒超时；
三项重启字段必须同时配置，上限只能为 1～3 次，不包括第一次运行。
可继续在异常处理章节声明原有规则。只使用此兜底时允许不声明任何分类规则。
旧程序不认识 `exception-restart@1` 时应拒绝加载，避免悄悄忽略次数限制。
CLI 能力声明为 `workflow.exception-restart@1`。

## 执行顺序

1. 正常条件和步骤的预期失败去向先执行，重试次数用完不是异常。
2. 用户停止进入停止与结束处理；执行例外仍优先按配置处理。
3. 真正异常截图交给 VLM 分类，唯一匹配的已配置处理方法优先。
4. 分类成功、没有匹配处理方法时，选择“从头执行”兜底；此时不再额外尝试模型临时点击建议。
5. 第一次出错后异常重启第 1/3 次；最多重启三次，共最多四轮。
   第四轮仍遇到未匹配异常时终止，不再等待人工继续，最终执行结束处理一次。

配置处理方法执行失败、次数用完、Agent 请求失败或超时，不等于“没有匹配类型”，
保留原有人工等待机制，不自动扩大为重启。权限拒绝、后台操作拒绝及其他只读诊断场景
不触发重启；无法截图（含锁屏）或无法分类时也不盲目重跑。
未配置本能力的流程继续使用现有异常恢复和人工等待。

## 重启边界和结果

重启从第一个普通执行步骤开始，跳过标记为异常处理或结束处理的步骤。
锚定窗口保留并刷新校验，不重新启动应用，不假设界面已恢复到初始页面；
流程前几个步骤必须能从当前页面回到所需起点。窗口校验失败保留现场交给平台处理。

清除本轮流程变量、循环计数和原步骤恢复探测状态；保留参数、已保存输出、
锚定窗口、累计异常重启次数，以及整次任务的异常规则/例外使用次数。
不保证程序扩展模块内部状态、外部应用状态、剪贴板或未显式保存的数据自动回滚。
中途重启不执行最终结束处理，正常完成、用户停止或最终终止时才执行一次。

运行变量 `异常重启` 提供 `count`、`maximum`、`source`、`error`；
达到上限时 `终止原因.kind` 为 `异常重启次数已达上限`。
日志显示 `异常重启第 1/3 次`，运行状态的 `exception_recovery` 保存重启次数、上限、来源和目标。
达到上限时状态为 `restart-exhausted`，不将缺失的临时变量拼成一条新的业务结果。

发送、提交、付款等动作可能在重跑时重复执行，流程作者必须先检查完成状态或使用业务去重标识。
平台不推断具体应用的去重规则，也不清空已保存结果；结果投递应能处理重复数据。
