# 步骤失败后的 VLM 选择判断

当前主线已统一为 Agent 阶段，见 [观察、执行、验证](workflow-agent-phases.md)。本文件仅保留为语言2迁移参考。

2026-10-19 源码新增能力。先检查安装版 `cli capabilities` 是否包含
`workflow.vlm-choice@1`；流程基本信息声明 `引擎能力：vlm-choice@1`。
这不是新的模型 Provider，也不接入 Jev 服务；使用当前配置的视觉模型，借鉴有界选择题的设计。
本次仅实现 Choice，不实现 Score 或概率判断，不依赖模型自报置信度作为放行标准。

## 步骤声明

```markdown
- 失败：等待 2 秒；重试 2 次；仍失败调用 VLM
- VLM判断：当前页面是否已返回列表？
- VLM选项【已返回】：可见完整列表及其页面标题 → 继续下一步
- VLM选项【仍在详情】：可见详情正文及关闭按钮 → 执行步骤【关闭详情】后重新验证
- VLM选项【尚在加载】：可见加载指示且没有错误提示 → 重新验证
- VLM选项【登录失效】：可见明确登录提示 → 跳到步骤【等待登录】
- VLM选项【无法确定】：证据不足或不属于其他选项 → 等待人工
- VLM超时：60 秒
- VLM最多判断次数：3 次
- VLM兜底：等待人工
```

选项格式为 `VLM选项【唯一名称】：判断依据 → 去向`，也支持 `->`。
至少两个选项；必须包含“无法确定”，其去向仅可等待人工或停止流程。
问题与每个选项应描述具体可见证据，避免要求 VLM 从没有展示的页面或历史动作推断结果。

允许的去向：

| 写法 | 含义 |
| --- | --- |
| 继续下一步 | VLM 按声明的可见依据确认结果；不重复原动作，执行原步骤成功控制（含成功跳转/停止） |
| 重新验证 | 只重新执行原步骤验证，不重放原动作；仍失败可再次判断，受次数上限约束 |
| 执行步骤【名称】后重新验证 | 执行一个已声明的普通 engine 动作步骤，再回原步骤只验证；不沿恢复动作的成功跳转继续业务 |
| 跳到步骤【名称】 | 按流程作者声明的路线继续业务；不表示原步骤已验证成功 |
| 等待人工 | 保留结果与进度；用户继续后重新验证原步骤，不重放原动作 |
| 停止流程 | 记录策略停止原因，再执行已有结束处理 |

普通恢复动作仍是可复用的普通步骤，流程作者须安排正常成功路线跳过它，避免在主线中再次执行。
恢复目标不能是分支、循环、Agent、结束处理或异常处理专用步骤，也不能自己包含 VLM 判断。
“重新验证”及恢复后复核要求原步骤存在验证条件。普通跳转不能跳入异常处理专用步骤。
VLM 判断仅用于普通 engine 的页面动作及验证；不能与旧“异常恢复”、步骤旧异常规则引用混用，
也不能代替保存为、逐项输出或新窗口登记所需的数据。需要这些能力时，将页面确认拆成独立步骤。

## 流程级异常处理的职责

流程级不增加总模式或新开关。原有公共异常分类规则继续保留；新增共享默认值，步骤可以覆盖：

```markdown
## 异常处理

- 超时：60 秒
- 最多总恢复次数：10 次
- VLM最多判断次数：3 次
- VLM兜底：等待人工
```

存在步骤 VLM 判断时，该章节可只声明默认值，不必虚构异常规则或识别指令。
旧规则的“识别指令”仍用于通用异常分类，不代替步骤的“VLM判断”问题。
旧异常规则、异常重启和恢复入口保持兼容；新语法不改变未声明 VLM 判断的旧步骤。

未写流程级章节时：判断超时 360 秒、连续失败的单步骤最多 3 次、总异常恢复上限 10 次、兜底等待人工。
写了流程级章节而省略“超时”时，保留旧章节默认的 300 秒。
单步骤判断次数为 1～10 次；步骤超时沿用 Agent 超时限制（大于 0 且不超过 86400 秒），
流程级超时仍为 1～3600 秒。总恢复上限沿用 1～100 次，同时约束此运行内的新判断和旧异常恢复计数。
单步骤成功后清除连续失败计数；总次数不清零。VLM 不可用、超时、截图失败、非法返回、次数耗尽，
都进入步骤覆盖或共享的 VLM 兜底（仅等待人工或停止流程）。

## 执行优先级与安全边界

1. 用户主动停止直接退出业务执行，不提交 VLM；已有结束处理照常执行。
2. 原动作按声明进行本地有界重试或检查；成功不调用 VLM。
3. 能力拒绝保留原错误；已声明的例外异常按原规则处理。
4. 明确声明“仍失败调用 VLM”的步骤先执行自己的选择判断，不被旧停止/跳转或通用异常恢复吞掉。
5. 未声明新判断的步骤继续使用原有失败终点及通用异常恢复机制。

调用前检查 Agent 总开关、授权和 Provider 配置，通过后才截图和分派；总开关关闭不被流程覆盖。
截图仅来自绑定窗口/步骤声明区域，并沿用窗口可见、身份及截图范围检查。
模型只收到截图、问题、选项依据、失败步骤和错误，不获得屏幕操作授权。
仅接受 `choice` 与非空 `evidence` 两个字段，程序验证选项再选择作者声明的路线。
非法选项、额外动作字段或缺失依据走兜底，绝不执行模型生成的坐标或代码。
后台输入安全拒绝和致命错误可以只读诊断，但不允许 VLM 放行继续、跳转或恢复点击；
人工后也必须实际验证通过，不能靠再次选择绕过拒绝。

运行日志记录选择、依据、兜底及路线，现场旁保存 `.vlm.json`，并更新 `exception_observation`。
流程详情概览显示声明的判断数量、共享默认值及其与旧失败字段的优先级。
Windows 与 macOS 共用 Python 编译/执行层；本地自动化测试不代表真实 Mac 或 Provider 验收。
