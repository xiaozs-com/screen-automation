# 工作流代码的信任边界

工作流结构检查、AST 检查和权限提示不是代码沙箱。包含 Python SDK 入口或
Markdown Python 扩展的工作流是受信任代码，可以使用当前用户的文件、网络和程序权限。
权限声明约束 SDK 调用，不会限制任意 Python 代码。只安装自己编写或来源可信的流程。
文件 API 的 base 目录用于解析相对路径，不是目录沙箱；绝对路径仍受当前用户的系统文件权限约束。

托管工作流在独立工作进程中运行，但该进程仍使用当前用户身份。这种进程分离便于
停止和记录结果，不构成操作系统权限隔离。真正的低权限运行环境需要单独设计和验收。

流程以可读的 `workflow.md` 编排；必要的 Python 扩展遵循公共 SDK 和声明的任务范围。
高风险操作仍由用户在场完成，不能因为代码有系统权限就将其交给扩展自动执行。
