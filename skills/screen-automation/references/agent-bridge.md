# 流程调用 Agent：配置与运行

屏幕自动化小助手桌面端可在运行流程时调用已配置的 Agent；平台 Agent 则通过工具调用小助手。

## 先确认调用方向

平台 Agent（如 WorkBuddy）通过小助手 CLI 观察和控制本机，是本 Skill 的日常使用方式。
这不要求在小助手桌面端配置“Agent接入”。

小助手运行流程时，需要模型参与观察、执行、验证或失败判断，才通过“Agent接入”调用 Provider。
当前平台能调用小助手，不代表小助手可以反向调用该平台；以真实配置和探测结果为准。

## 配置与按需引导

基础任务直接使用基础能力。只有语义定位、页面理解、智能执行或智能异常判断能帮助当前流程时，
简短解释用途，再由用户在“小助手 → 设置 → Agent接入”选择 Provider、模型并测试连接。
凭据在用户界面配置，不在对话中索取、不写流程或命令参数。

先用 `cli capabilities` 核对阶段接口，`cli access list` 核对所需组件与访问状态，
`agent status` 查看配置摘要；需要实际探测时使用 `agent probe`。
各结果分别代表接口、扩展状态和 Provider 就绪情况，不能互相替代。未就绪时说明原因；
用户可以继续完成可用的基础任务，也可准备标明前提的草稿。

## 智能阶段与授权

详细语法见 [阶段契约](workflow-agent-phases.md)。观察、执行、验证各自可选程序或 Agent，
失败处理按现场证据选择有次数上限的预设路线。文字或变量输入使用文本能力，区域截图使用视觉能力。
观察、验证和失败判断只读；改变屏幕的 Agent 执行须明确 `允许操作：屏幕操作`、
相应流程权限及后置验证。只读判断不能附带点击、输入或模型生成的任意代码。

所有 Agent 阶段与外部工具均遵循 Skill 的用户在场边界：账号登录、账号授权、身份验证、
凭据输入、支付及其他高风险操作暂停交给用户，不能因有屏幕操作权限而代办。
用户完成后重新观察验证，不能把“用户继续”视为业务已成功。

## 视觉与隐私

截图外发前说明 Provider、读取范围和用途并取得确认。仅采集授权区域，避开密码、验证码、密钥及
无关隐私；模型和日志都不接收原始凭据。文本任务不截图，也不要求视觉模型。
VLM 必须真实支持图片输入；能力不匹配时先停止视觉调用，不能先截图上传再尝试。

Provider 不能调用、未授权或离线时，保留诊断，按已声明路线等待用户或停止。
由某 Provider 启动的流程再次调用同一 Provider 可能触发 `recursive_agent_call`；
遇到该错误停止递归，调整流程边界，不无限重试或绕过工具限制。

## 诊断与验收

`agent status/probe` 检查小助手调用已配置 Provider 的链路。
`runs pending-agent`、`runs agent-context/claim/complete/fail` 是外部 Agent 领取和回填任务的集成接口；
普通用户在界面配置即可，不需要手工运行领取命令。

连接成功后先测试无敏感信息的文本或只读区域，再验收流程中的定位、操作和验证。
设置中的屏幕理解测试只证明一次授权区域读取，不等于完整流程成功。
语法有效、Provider 连通、真实页面结果正确分别报告；不能以单画面测试替代业务验收。
