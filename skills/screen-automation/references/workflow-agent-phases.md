# 观察 → 执行 → 验证：流程语言 3

能力 `workflow.agent-phases@1`，流程基本信息声明 `引擎能力：agent-phases@1`。
Agent 可用 `cli workflow schema steps` 读取当前阶段格式，`cli workflow sdk` 读取程序动作接口。
以当前能力返回、schema 和运行结果确认接口与可用状态。

## 智能贯穿每个阶段

产品理念是“基于实时观察的智能定位、智能执行、智能异常处理（需配置好“Agent接入”）”。根据当前画面理解目标和组织执行，页面变化或失败时重新观察并选择已声明路线。坐标、OCR、UIA 与浏览器动作是可组合的执行手段。

智能能力既可参与正常执行，也可参与失败处理。观察、执行、验证各自选择程序或 Agent：

- 智能观察：根据当前画面理解页面、定位唯一目标，或从画面/文字提取结构化信息。
- 智能执行：使用本步观察结果和明确任务完成工作；文本任务不需要屏幕操作，改变屏幕须显式授权并验证。
- 智能验证：重新读取执行后的画面或数据，判断业务结果，不以命令返回成功替代验收。
- 智能失败处理：按当前现场选择预先声明的有限路线，必要时调用恢复步骤，再重新验证。

可以采用“Agent 观察 → 程序执行 → OCR 验证”，也可以采用“程序或 Agent 观察 → Agent 执行 → 程序或 Agent 验证”。
无需每步都调用模型。确定性条件和动作使用程序；需要页面含义理解、动态定位或任务推理时使用 Agent。
观察结果不是永久坐标或自动操作授权。观察、验证、失败判断保持只读；Agent 执行受用户任务和阶段授权约束。

账号登录、账号授权、凭据输入、支付及其他高风险操作始终交给用户在场亲自完成。
即使执行阶段已声明屏幕操作权限，也不能代办；观察和判断阶段不读取凭据，失败选项不能绕过人工交接。

## 机器可读接口

`cli describe` 的 `runtime_features.workflow_language_v3` 描述上述模型；`cli capabilities` 声明动作契约；
`cli access list` 与 `agent status/probe` 分别核对访问状态和 Provider，不能相互替代。
`cli workflow schema steps` 提供 `stage_contracts`、`result_schemas`、`result_variables`、
`input_requirements`、`execution_patterns`、`retry_semantics`、`agent_fields`、`defaults` 和 `result_contract`；调用方忽略未知新增字段。
默认结果格式与运行器共用同一定义：

| 任务 | 严格结果字段 |
| --- | --- |
| 判断 judge | passed=BOOLEAN, evidence=STRING |
| 定位 locate | found=BOOLEAN, box=INTEGER_LIST, evidence=STRING |
| 提取 extract | data=OBJECT, evidence=STRING |
| 执行 execute | completed=BOOLEAN, data=OBJECT, evidence=STRING |
| 选择 choice | choice=STRING, evidence=STRING |
| 现场处理 repair | action=STRING, box=INTEGER_LIST, evidence=STRING |

`evidence` 必须非空；定位框是当前截图内像素坐标，未找到时 `found=false, box=[]`。
执行可用 `结果格式` 声明任务字段；运行器补充并校验 evidence，命名结果在验证通过后才导出。
没有新增绕过流程授权的自由 Agent 操作 CLI 或 Python SDK 方法。

## 用户只需要读步骤

```markdown
<!-- 屏幕自动化流程语言：3 -->
```

每个步骤按“观察、执行、验证”组织，失败处理和下一步就在当前步骤。
程序方式沿用 OCR、模板、程序扩展、浏览器、鼠标键盘等既有能力；需要智能时，该阶段选择 Agent。
文字或变量输入走文本能力；区域截图输入要求视觉能力。流程不必写 LLM/VLM，也不自动改换 Provider。
所有 Agent 阶段都受 Agent 接入总开关、授权、Provider 配置和超时限制。

```markdown
### 关闭文章，返回列表

- 观察：
  - 方式：Agent
  - 输入：区域【内容区】
  - 定位：当前文章详情的唯一关闭按钮，不能是图片里的图案
- 执行：点击观察结果
- 验证：
  - 方式：Agent
  - 输入：区域【内容区】
  - 判断：是否已经显示历史文章列表
- 失败：
  - 重试：2 次
  - 间隔：2 秒
  - 仍失败：等待人工
- 下一步：步骤【选择下一篇】
```

简单程序步骤不用展开：

```markdown
- 观察：区域【内容区】出现文字【保存】
- 执行：点击区域【内容区】中的文字【保存】
- 验证：区域【内容区】出现文字【已保存】
- 失败：等待 2 秒；重试 2 次；仍失败停止
- 下一步：继续下一步
```

程序和 Agent 可任意混合。例如观察用 Agent 定位，执行由程序点击，验证用 OCR。
也可写 `方式：程序`，观察/验证的子字段为 `条件`，执行的子字段为 `动作`。
没有需要时可以省略观察、执行或验证；省略执行的步骤仍会执行声明的验证。
程序扩展、浏览器动作和数据保存的句型继续复用，不另建一套执行器。

## Agent 阶段怎么写

每个 Agent 阶段声明 `方式：Agent`、`输入`，再从以下任务中选一个：

| 环节/任务 | 写法 | 程序收到的结果 |
| --- | --- | --- |
| 观察定位 | `定位：目标描述` | 是否找到、截图内目标框、可见依据 |
| 观察理解 | `判断：明确问题` | 是否满足要求、依据 |
| 观察提取 | `提取：需要哪些信息` | `data` 对象、依据 |
| 执行 | `指令：要完成的任务` | 完成状态、`data`、依据 |
| 验证 | `判断：动作后应满足什么条件` | 是否通过、依据 |

输入可用 `区域【名称】`、当前 `操作区域【名称】`、`变量【名称】`、`文字【文本】`。
定位只能使用区域截图。观察、验证、失败判断默认只读，不能声明操作授权。
Agent 执行只有在显式写 `允许操作：屏幕操作` 且流程声明相应鼠标/键盘权限时才获得操作能力。
授权屏幕操作的 Agent 执行必须声明执行后验证。
默认超时 180 秒，可在阶段内写 `超时：60 秒`。文本输入不截图，不要求视觉模型配置。

当前步骤可使用变量 `观察结果`、`执行结果`、`验证结果`，用于给下一阶段提供信息。
要跨步骤保留结果，使用原有 `保存为：变量【名称】`。
Agent 执行可声明 `结果格式`，沿用类型化结果约定，平台额外要求 `evidence=STRING`；声明的命名结果在本步骤验证通过后导出为变量，当前验证阶段通过“执行结果”读取尚未确认的结果。

定位结果是当前步骤的一次性内部目标。执行前检查窗口身份、位置、截图尺寸、目标框范围、
目标局部画面及有效期；不会把一份旧截图的位置长期当作坐标使用。
动作重试时重新观察和定位；`最多检查`只重复验证，不重放已执行动作。
Agent 验证一次不通过就进入有界重试，不在短间隔轮询中反复调用模型。

## 判断之后去哪

观察中需要分支时使用有限选项：

```markdown
- 观察：
  - 方式：Agent
  - 输入：变量【文章内容】
  - 判断：文章是否符合本轮采集要求
  - 选项【符合】：满足已说明的主题和日期要求 → 继续下一步
  - 选项【不符合】：有明确不符合依据 → 跳到步骤【下一篇】
  - 选项【无法确定】：信息不足 → 等待人工
```

观察中的“继续下一步”指继续当前步骤的执行阶段；失败判断中的“继续下一步”指确认当前步骤已完成，
进入它声明的正常成功路线。需要跳过整个步骤时写“跳过本步骤”；跨越同一项的多步处理时写明确跳转。
至少两个选项，必须有“无法确定”。观察阶段的去向只能等待人工或停止；失败阶段可选择重做、重新验证、跳过本步骤或跳到明确业务步骤。只有显式声明等待人工的路线才会等待人工。
验证只判断是否通过，复杂选择和去向写在观察或失败中。
观察选项只允许继续、跳转、等待、停止；恢复重试放入失败处理。

## 失败处理也在步骤内

先读取当前主程序 `cli workflow schema steps` 的 `failure_contract`。新增字段与可选动作以返回值为准；
旧版没有 `scene_repair` 或 `direction` 时，不生成相应块，说明升级前提或使用已支持的明确程序路线。
对保存、提交等已有副作用的动作优先“最多检查”，只有确认可重放时才“重试”。


```markdown
- 失败：
  - 最多检查：6 次
  - 间隔：2 秒
  - 仍失败：Agent
  - 输入：区域【内容区】
  - 判断：目前是否已返回列表，或被图片放大层遮挡
  - 选项【已返回】：能看到公众号历史文章列表 → 继续下一步
  - 选项【图片遮挡】：可见图片放大浮层及关闭按钮 → 执行步骤【关闭遮挡】后重新验证
  - 选项【仍未返回】：没有遮挡但仍在详情 → 重新执行
  - 选项【无法确定】：当前项无法可靠恢复 → 跳过本步骤
  - 最多处理次数：2 次
  - 兜底：跳过本步骤
  - 次数耗尽时：跳过本步骤
```

`重试`会重新观察并执行；`最多检查`只检查结果，二者只能选一个。次数可用已有参数引用（参数化次数用最多检查）。
“仍失败”也可直接写等待人工、停止流程、跳到步骤、重新执行或重新验证，无须调用 Agent。
“重新验证”及恢复后复核要求本步骤声明验证条件，不重放原业务动作。
有“保存为”的数据步骤不能用失败 Agent 的“继续下一步”来代替缺失数据；应重新执行或走明确业务分支。
失败处理默认最多 3 次，可设 1～10 次。Agent 不可用、截图失败、超时或无效返回走“兜底”（兼容旧字段“不可用时”）。
有 Agent 后续判断时默认兜底为跳过本步骤；无 Agent 的缺省失败终点仍安全停止。显式人工等待配置保持兼容。
次数耗尽走“次数耗尽时”，不能重做或重新验证；兜底是重做/重新验证而未写耗尽路线时，耗尽默认跳过本步骤。
跳过与成功不同：不伪造结果，清除本步保存变量并记录“步骤跳过结果”；跨多步骤处理同一项时，须显式跳到该项的恢复/跳过入口。
用户主动停止不交给 Agent；安全拒绝和能力不可用不能被模型放行成成功或恢复点击。
未声明失败处理的步骤安全停止，新格式不继承隐式的全局 Agent 异常处理。

非关键项示例允许跳过；关键步骤应显式改为等待人工或停止。Agent 必须返回声明选项的结构化结果，
不能以证据文字中的“可由程序记录跳过”触发路线。对逐项处理的流程，跳过一步只推进一步；
若当前项还有后续步骤，选择跳到该项的跳过/下一项入口，且先确认已恢复列表等下一项所需页面。

### 现场处理与后续方向分开配置

流程作者按步骤重要性选择恢复方式和终点。下面是非关键步骤的示例：

```markdown
- 失败：
  - 现场处理：
    - 方式：Agent
    - 输入：操作区域【锚定窗口】
    - 指令：关闭临时遮挡并恢复本步骤现场；不提交或删除业务数据
    - 允许操作：点击
    - 最多操作：3 次
    - 超时：30 秒
  - 后续方向：
    - 方式：Agent
    - 输入：操作区域【锚定窗口】
    - 判断：根据新截图及现场处理结果，选择重做或跳过
    - 选项【可以重做】：已恢复到本步可执行状态 → 重新执行
    - 选项【无法确定】：不能处理当前项 → 跳过本步骤
  - 最多处理次数：2 次
  - 兜底：重新执行
  - 次数耗尽时：跳过本步骤
```

两个块都可省略：只写后续方向就只判断；只写现场处理并设置“仍失败：重新验证”等路线，就由程序决定后续。
关键步骤可把兜底和次数耗尽路线显式设为“等待人工”或“停止流程”；没有隐式人工等待。
后续方向只读，能看到独立的新截图以及“现场处理结果”；现场未解决或出错仍可决定重做/跳过。

现场处理目前支持点击。Agent 自行选择当前画面中的目标，返回 `click`、`finished` 或 `unresolved`，
底座验证截图内目标框、窗口身份及画面是否变化，异步显示真实大小目标框 0.5 秒，同时继续执行点击；不等待提示框显示结束。
每次动作后重新截图核对，最多点击次数由底座执行，不依赖提示词；超时是整次现场处理的总时限。
Agent 现场恢复仅尝试当前步骤范围的点击，不跨到后续业务、不扩大权限；需要输入或其他动作时使用已支持的程序恢复步骤。
观察与点击在同一交互锁内，锁等待不计入该总时限；结束后释放锁，再进行后续方向判断。
Agent 不获得任意外部操作工具权限，因此只支持判断的视觉 Provider 也可参与本地点击恢复。
流程必须声明点击屏幕权限。Agent 的“finished”只是现场处理报告，不能替代本步业务验证；
含现场处理的“继续下一步”必须有本步验证，并按重新验证执行，不直接当作成功。

显式选择“执行步骤【恢复步骤】后重新验证”时，恢复步骤失败也返回原步骤的有限失败路线，
不会额外弹出隐式人工等待。用户停止、权限拒绝与底层能力不可用仍保留原有中止边界。

明确的特殊错误可以就地写，不再另找“例外异常”章节：

```markdown
  - 遇到【标题已确认不匹配】：
    - 错误包含：文章标题已确认不匹配，按规则跳过
    - 处理：跳到步骤【检查跳过时的页面】
    - 最多次数：100 次
```

该配置是失败块的子字段，可以用错误类型或错误包含匹配；必须明确条件，不能无条件吞掉所有异常。
正常业务判断继续使用对应步骤的如果/则/否则，不能以“程序报错”猜测业务已正常结束。

## 公共恢复动作与结束处理

复用的恢复步骤仍放在“执行步骤”内，声明 `用途：恢复处理`，平时跳过，调用时执行并返回原步骤验证。
恢复步骤同样可以使用程序或 Agent 观察、执行、验证。入口不能是分支、循环或嵌套恢复调用；
恢复动作失败时保留现场等待人工，不反复重放它。
`结束处理`章节保留为生命周期入口，具体保存摘要、投递、确认等动作仍写在步骤内；首次停止照常收尾。
失败判断及已知错误均在本步声明，不另设全局异常章节。

## 完整示例：智能观察 → 智能文本执行 → 智能验证

此示例只处理流程中给定的文字，不截图、不授权点击输入。运行前仍须确认 Agent 接入和文本 Provider 可用。
真实屏幕任务可把观察输入改为已声明区域，再按授权决定由程序点击或交给 Agent 执行。

```markdown
<!-- 屏幕自动化流程语言：3 -->

# 整理一条任务信息

## 基本信息
- 标识：agent-text-summary
- 版本：0.1.0
- 用途：提取给定文字、整理摘要并验证
- 目标系统：Windows、macOS
- 权限：读取屏幕
- 引擎能力：agent-phases@1

## 参数
- 内容区域：RECT(left=10,top=20,right=300,bottom=400)

## 锚定窗口
- 标题包含：示例程序
- 找不到时：提示用户重新选择

## 坐标与区域
- 区域【内容】：操作区域【锚定窗口】内 参数【内容区域】

## 执行步骤

### 整理并核对
- 在：区域【内容】
- 观察：
  - 方式：Agent
  - 输入：文字【任务是整理今天的会议记录，完成标志是得到摘要和待办清单。】
  - 提取：任务目标与完成标志
- 执行：
  - 方式：Agent
  - 输入：变量【观察结果】
  - 指令：把提取的目标和完成标志整理为简短说明，返回到 data 对象，不操作屏幕
- 验证：
  - 方式：Agent
  - 输入：变量【执行结果】
  - 判断：是否已完成整理，且 data 包含任务目标及摘要和待办清单这两个完成要求
- 失败：
  - 重试：1 次
  - 间隔：1 秒
  - 仍失败：等待人工
- 下一步：继续下一步
```

## 验收与诊断

先检查 `agent status`、`agent probe` 和安装版能力；本地包执行 `cli workflow inspect <路径>`，
安装后执行 `cli workflow validate <流程标识>`。
语法检查不能证明 Provider 执行、目标页面或业务结果正确。先以无敏感信息的文本/只读区域验收，
再按任务授权验证智能定位、程序点击或 Agent 执行及后置验证。
分别检查目标不唯一、画面变化、模型无效返回、次数耗尽、人工继续、用户停止和结束处理。
不能把 Windows 模拟测试称为真实模型、业务流程或 Mac 真机验收。
