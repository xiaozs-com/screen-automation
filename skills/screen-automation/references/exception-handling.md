# 流程级与步骤级异常处理

完整系统规则及判断顺序见[流程异常处理系统规则](workflow-exception-system.md)。
例外异常与终止收尾语法见[例外异常与结束处理](workflow-lifecycle.md)。

先检查安装版 `cli capabilities` 是否包含 `workflow.exception-handling@1`。
此能力需要更新主程序；1.3.5 及以前的安装包不识别下列新语法。
VLM 服务仍需用户已配置的 Agent 接入。规则属于独立流程，不内置任何具体应用操作。

## 平台默认兜底

在 GUI/运行管理器启动的流程中，只要启用 Agent 接入，就默认提供异常截图、VLM 诊断和
人工等待，不要求流程声明“异常处理”章节。未声明时使用 360 秒读图超时，最多自动尝试 10 次。
流程声明的规则优先于模型建议；步骤“异常处理：禁用”仅禁用自动恢复动作，仍会诊断和等待。
步骤中的后台输入拒绝、致命验证错误仅进入只读诊断与人工等待，不放宽 SDK 权限或改用真实鼠标。
用户主动停止立即请求停止业务步骤，不进入 VLM；已配置的结束处理仍执行，收尾完成后退出。
尚未确认锚点或锁屏等无法取得有效截图时，记录原因并等待人工处理。
正常到达“完成”步骤不属于异常，不会因此提交 VLM；业务上的完成条件仍由独立流程声明。
列表扫描结束但存在未找到项目、达到采集上限、数据已存在、超出日期范围，属于可预期业务结果；
由流程保存摘要并正常分支或收尾，不应统一抛异常后反复调用 VLM、无限等待用户。
页面遮挡、操作效果不符、OCR 无法确认等未知执行问题仍提交 VLM；锁屏、窗口关闭等无法
取得有效截图的情况说明原因并等待，不能要求模型猜测不可见画面。
Python SDK 的 `ctx.step.perform` 同样继承此默认规则，保留调用栈并从失败步骤重试；
Markdown 执行器负责自己的兜底，避免同一异常被底层 SDK 和流程层重复提交。
Python 中未通过步骤 API 执行的任意程序错误不具备可恢复的步骤边界：同样诊断并保留运行等待，
但明确提示“继续仅重新诊断”，不能声称可以跳回异常语句或偷偷重跑整个脚本。用户停止才结束等待。

## 配置默认规则

```text
## 异常处理
- 识别指令：判断图片放大、意外菜单或未知。observation 包含 menu_open、confidence、reason。
- 超时：360 秒
- 最多总恢复次数：10 次

### 规则【图片恢复】
- 异常类型：图片放大
- 处理：步骤【退出图片】
- 最多恢复次数：2 次
- 恢复复核：步骤验证
- 恢复入口：出错步骤
```

普通步骤失败且常规重试耗尽后，主程序保存出错窗口截图，提交观察专用 Agent 分类。
固定返回格式为 `category=STRING`、`observation=OBJECT`，其中 category 必须匹配
一个可用规则的异常类型。分类、置信度、理由和辅助字段会显示在运行日志，另存为现场旁的
`.vlm.json`，并通过运行状态的 `exception_observation` 返回，供 GUI 和外部 Agent 查询。
一次识别可在 observation 内返回多个辅助字段，不限于“是/否”。

优先执行已配置的规则。未匹配规则时，VLM 可在 `observation.recovery` 提出
`{action:"click",point:[屏幕绝对x,屏幕绝对y],confidence:0.99,reason:"依据"}`。
当前只执行一次关闭临时遮挡的坐标单击，要求置信度至少 0.95、坐标位于现场区域内，
且目标窗口身份和大小未变；通过现有 SDK 和流程已授权的输入方式执行，不自动改换前后台模式。
不得建议提交、删除、发送等业务动作，也不执行模型返回的任意代码或命令。
单击后等待 2 秒，再截图交给 VLM 复核；必须明确 `recovered=true` 且置信度至少 0.95。

没有可靠建议、复核失败、恢复步骤失败、次数耗尽、Agent 超时、未配置 Agent 或截图失败时，
托管流程保留变量、步骤进度和已产生结果，进入“等待用户处理”，不因这些情况直接退出。
用户处理页面后点击现有“继续”按钮，从当前步骤重新检查和重试；不会从流程开头运行。
等待没有自动超时，用户可点击“停止”。恢复步骤失败时仍提交 VLM，但禁止自动反复点击。
独立脚本环境没有运行管理器与继续按钮时，报告需要人工处理的错误。

正常运行不持续调用 VLM，也不保证在画面刚变化的瞬间触发；任意受此配置覆盖的
步骤出现异常后才触发。启动窗口确认失败进入人工等待；用户主动停止不进入恢复机制。
后台安全拒绝和平台致命错误只读诊断，不自动执行恢复动作。

## 处理步骤

在执行步骤中保留可见的操作和验证：

异常处理是平台调用的子过程，不是主流程跳转后再自行寻找出口的普通步骤链。
平台保存出错步骤、出错窗口及返回方式。处理动作执行到该规则的处理块末尾，或声明
“成功：结束异常处理”，都会按保存的返回点自动返回；不必配置下一步或显式结束指令。
恢复规则可配置“恢复复核”：默认“步骤验证”，不额外调用 Agent；“Agent”才请求模型复核异常消失；
“人工确认”等待用户确认后返回。步骤验证模式由处理步骤及返回后的业务验证判断结果，
处理步骤自身失败则等待人工确认，不盲目重放恢复点击。模型临时建议的点击仍须读图复核。
默认 `恢复后：自动返回`（可省略）：返回原步骤，先检查其结果验证；若已完成，沿原步骤的
成功分支继续，避免再次点击；否则重新检查并执行该步骤。显式重试、继续下一步及指定跳转仍兼容。

选择 Agent 复核时只确认匹配的异常是否消失，不依赖公众号、文章等尚未建立的业务变量。
原步骤的业务条件由返回后的原步骤检查。处理步骤验证失败时也可交给平台复核；
若异常已经消失便返回原流程，不再反复重放退出图片等动作。
Agent 复核未确认消失则等待用户；点击“继续”后重新复核当前截图，而不是重新执行整段处理动作。

```text
### 退出图片
- 用途：异常处理
- 在：出错窗口
- 动作：执行程序扩展【准备恢复坐标】
- 保存为：变量【恢复状态】

### 点击退出
- 用途：异常处理
- 在：出错窗口
- 动作：点击 变量【恢复状态.point】
- 等待：2 秒

### 确认恢复
- 用途：异常处理
- 在：出错窗口
- 动作：等待 0 秒
- 验证：程序扩展【页面正常】
- 成功：结束异常处理
- 失败：等待 2 秒；最多检查 3 次；仍失败停止
```

示例中的扩展函数需要由流程实现。处理步骤只在异常期间执行，正常路径自动跳过；
“在：出错窗口”使用出错步骤的窗口基准，支持多锚定窗口。
处理块结束后，主程序根据保存的返回位置自动返回，由原步骤继续验证。
若要在返回前额外确认，可明确选择 Agent 或人工确认，不隐式增加模型调用。
菜单坐标等临时状态在恢复后可能失效：对应规则应配置“恢复后”跳到重新定位的准备步骤，
不要直接重放保存的旧坐标。

处理方法也可直接复用现有普通动作步骤：`处理：步骤【打开历史消息】`。
平台把该步骤当作一次子调用，保留其动作、等待和验证，执行完便复核、返回中断处，
不跟随它在主流程中的“下一步”或成功跳转。复用目标不能是分支或循环步骤；
复杂处理继续使用“用途：异常处理”的处理块。

`异常判断` 保存 category、observation；`异常恢复现场` 保存截图、目标身份及原始错误；
`异常恢复来源` 保存出错步骤、操作区域、匹配规则及恢复次数。
VLM 结果只是数据，流程在动手前还应核对分类可信度及截图以来窗口身份、位置是否改变。

## 步骤覆盖

- `异常处理：默认`（可省略）：使用默认启用的流程规则。
- `异常处理：禁用`：禁止自动恢复动作，适合提交、发布等有外部副作用的步骤；平台仍诊断并等待。
- `异常处理：规则【专用规则】`：只使用这条规则，覆盖流程默认规则。

专用规则与默认规则放在同一章节；专用规则可声明 `默认启用：否`，防止影响其他步骤。
同一异常类型只能有一条默认规则。旧步骤级 `异常恢复 / 预期页面 / 最多恢复次数`
继续兼容，并优先于默认规则；`异常处理：禁用` 则明确禁用两者。

### 统一恢复入口

新规则建议使用 `恢复入口：出错步骤`（默认行为），或 `恢复入口：步骤【重新准备菜单】`。
指定入口必须是普通主流程步骤，不能是异常处理步骤或结束处理步骤。
入口在进入恢复时与出错步骤、恢复方法一起保存；人工继续使用同一个已保存入口，不让模型重新猜测。
临时菜单、剪贴板基线或坐标失效时，应指定到重新准备和定位的步骤。
默认返回出错步骤时先验证是否已完成，已完成则继续，不重复动作；指定准备步骤则按该步骤重新执行。
旧字段 `恢复后` 继续兼容，但不能与 `恢复入口` 同时配置，避免互相冲突。
日志及运行状态 `exception_recovery` 保存 source、handler、destination 和 status，详情末尾显示恢复路线。

恢复步骤自身失败交给平台复核及人工等待，不递归执行恢复点击；处理动作仍可使用有界等待。
每个出错步骤受匹配规则次数限制，整个流程另受总恢复次数限制，处理步骤循环也有上限。
对于图片退出等非幂等动作，将“点击一次”和“反复验证”分为两个步骤，避免重试时重新打开图片。

## 人工处理提示与完整记录

进入人工等待时，主窗口显示醒目的黄色提示，并自动打开非阻塞详情窗；关闭详情不会停止或继续流程。
用户可同时操作目标应用，在详情窗点“处理完成，继续”恢复对应运行，不受主窗口当前选中行影响。
同一等待事件只自动提示一次；再次等待时可重新提示，也可从“查看详情 → 版本与运行 → 运行日志与 VLM 详情”打开。
采集屏幕期间请先暂停再查看详情；恢复采集时详情窗自动关闭，避免其文字进入 OCR 截图。
详情分为异常与识别历史、完整运行日志，可滚动选择复制。VLM 理由保留全文及换行，仍对凭据脱敏，
不再受到状态栏或默认短诊断长度的限制；已结束运行也可查看保存记录。

“最多检查 N 次”只反复检查结果，不重放点击；参数形式与直接数字的含义一致。
异常经 VLM 诊断后，若没有匹配的异常规则但步骤已声明“仍失败跳到步骤”，优先执行该已配置处理路线，
不因分类为“未知”而丢弃流程原来的跳过、返回等处理方法。
